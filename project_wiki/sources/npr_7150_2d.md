## Why It Matters

NPR 7150.2D is a public NASA procedural requirements document. It supports the project with NASA requirements for software life-cycle planning, requirements mapping matrices, software assurance, IV&V, reviews, audits, traceability, and source/software product access.

## Key Ideas

- The directive covers the complete software development life cycle, including planning, development, maintenance, retirement, operations, management, and assurance-related work.
- It does not impose a single life-cycle model but does require a standard set of requirements.
- Projects maintain requirements mapping matrices, including tailoring and rationale.
- Project managers require developer reporting and allow NASA/software assurance personnel to review verification activities, audit processes, participate in reviews, and access source code, traceability, change tracking, and nonconformance information.
- NPR 7150.2D has an explicit chapter section for software bi-directional traceability.

## Useful Claims

- NASA software governance treats requirements mapping, tailoring rationale, traceability, audits, and review participation as explicit management artifacts.
- A verification compiler should have a requirements mapping matrix analogue.
- Human/software assurance review needs access to source artifacts and traceability, not just summarized outcomes.

## Requirements Impact

- The verification compiler should maintain a requirements mapping matrix or equivalent.
- Tailoring and non-applicability decisions should be represented with rationale.
- Evidence packages should preserve access paths to source artifacts, trace links, change records, and review results.
